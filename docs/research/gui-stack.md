# GUI/windowing stack facts, this workstation (2026-09-26)

Facts only; no DAW GUI decision. `pacman -Q hyprland xorg-xwayland`: Hyprland `0.56.2-3`, XWayland `24.1.13-1`. `printenv DISPLAY WAYLAND_DISPLAY XDG_SESSION_TYPE`: `:0`, `wayland-1`, `wayland`. `ps -eo comm,args` shows `Xwayland :0 -rootless ...`, so X11 windows can run under this Wayland desktop. This does not imply that a native Wayland parent can directly embed an X11 plugin view.

`pacman -Q sdl3 glfw-x11 glfw-wayland`: SDL3 `3.4.16-1`; GLFW reports `3.5.1-1` through both virtual provider names. `pkg-config --modversion sdl3 glfw3`: `3.4.16`, `3.5.1`. A tiny `/tmp` program calling `SDL_GetNumVideoDrivers/SDL_GetVideoDriver`, compiled with `pkg-config --cflags --libs sdl3`, listed `wayland`, `x11`, `kmsdrm`, `offscreen`, `dummy`, `evdev`. `/usr/include/SDL3/SDL_video.h` defines `SDL_PROP_WINDOW_X11_WINDOW_NUMBER` as `"SDL.window.x11.window"` (line 1664), retrievable via `SDL_GetWindowProperties` and SDL number property access; corresponding Wayland display/surface properties exist. For the template X11 plugin editor, the DAW window must use the SDL X11 driver and pass its XID; a native Wayland SDL window has no X11 parent XID. GLFW is available but would need its native X11 access path for the same embedding and has less DAW-specific evidence here.

The template's `build-cmake/_deps/pugl-src/meson.build` says Pugl version `0.5.7` at pinned commit `b7637149ebe53124e5be90559e02a0185bbcbd73`. Its platform sources are X11, macOS and Windows; no Wayland backend was found. `plugin/gui/CMakeLists.txt:starter_pugl_target` compiles `src/x11.c` and `src/x11_gl.c` on Linux. It compiles upstream NanoVG plus `NanoVGBackend.c` (GL2) locally; macOS optionally uses `nanovg_metal`/`MetalBackend.m` and local Pugl Metal glue. NanoVG source has GL2/GL3/GLES backends in `src/nanovg_gl.h`, but this template chooses GL2 on Linux. `Window.cpp` embeds using `puglSetParent` with the host XID and handles backing ratio and design-space scaling.

`tools/linux_host_probe.cpp` calls `XOpenDisplay`, creates/maps `XCreateSimpleWindow` as an X11 parent, loads the CLAP, checks `CLAP_WINDOW_API_X11`, passes `clap_window_t.x11` to `gui->set_parent`, then verifies child mapping and captures parent pixels with `XGetImage`. It runs audio separately and tests resize, hide/show, three create/destroy cycles and timer cleanup. This is the concrete mechanism a DAW using an X11 SDL/GLFW top-level can reuse. `BUILDING.md` notes `--no-host-timer` validates lifecycle only because Pugl's X11 timer needs `puglUpdate` to dispatch; host-driven CLAP timer is needed for repaint liveness.

`pacman -Q mesa`: `1:26.2.3-1`. Neither `glxinfo` nor `eglinfo` is installed (`command -v` produced no path), so no GL version or Arc B580 renderer string was verified. The installed `libGL`/OpenGL development libraries were sufficient for the template's offline CMake configure, but that says nothing about runtime GL capability. A later read-only GL context probe could establish actual version on the active XWayland display.

Trade-offs to investigate: SDL3 has both Wayland and X11 window drivers plus broad input/accessibility and native window properties; forcing X11 for editor embedding means the DAW itself runs via XWayland. GLFW has a smaller window/input API and X11/Wayland support, with the same X11 embedding constraint. Pugl directly matches the template's plugin editor stack and native X11 parenting but provides no Wayland backend in this pinned version and is not a full DAW widget toolkit. NanoVG is renderer rather than windowing; the template's GL2 path is proven to configure, not yet measured for a large multitrack DAW UI. No final GUI stack selection is made here.

# Optimizer benchmark — variants

Best loss per run of `optimize.start` against each task's hidden reference; `pass` is best ≤ the task's `max_loss`.

Kept (`docs/specs/optimizer.md`, Amendments 2026-10-01): **initial σ = 0.05 for
reference targets** and **`"auto"` ranges as a window around each parameter's
current value** — the `2026-10-01-window-sigma-0.05` rows, where `auto` reaches
3 of 21 runs at or below `max_loss` (median 3.3) against the merged code's 0
(median 21.8), and the changed modules' parameters reach 10 of 21 (median 1.1)
against 9 (median 3.0). Profile-only targets keep σ = 0.2 and explicit key
ranges are unchanged.

Not kept, each measured here: the **restart** (0 of 42 runs reached its trigger
once σ and the window were in place), **reloading the clone's state per
candidate** (all 42 losses bit-identical, which rules out the slot-removal
failure mode for these tasks) and **rescaling the `trajectory` term** (it raises
the pass count 13 → 16 but makes the search's relative progress worse — a
re-calibration of the score, not a better search).

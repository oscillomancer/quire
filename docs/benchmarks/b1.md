# B1: engine capacity

**Result (2026-10-01, MOTU M4 via PipeWire-JACK, 48 kHz / 64 frames, Core Ultra
5 225F, `powersave` governor, revision 3226001):** with anticipative processing
the engine sustains **30 tracks** with zero xruns over a confirmed 300 s run
(N = 31 had one xrun); without it, even **N = 1 fails** (3 xruns in 300 s).
REAPER on the same session also fails at N = 1 ([b2.md](b2.md)). The target
"anticipative on ≥ 3× off" holds trivially (30 vs 0), but the zero says the
single-threaded callback cannot absorb this session's worst-case blocks at 64
frames: one playback chain (Orrery reference patch, 8-note chords × 3 unison
voices) plus the monitored chain. Average load is far below a core, so the
likely cause is per-block bursts (chord changes start and release 24 voices
in one 1.33 ms period) on a CPU that idles at low clocks; queued as a
diagnostic (worst-case block cost at 64 frames).

Notes: this workstation's `~/.config/pipewire/jack.conf.d` forces every JACK
client to quantum 128, so the first attempt was rejected as invalid (granted
128); the bench now sets `PIPEWIRE_QUANTUM=64/48000` for its own process. The
previous lighter Orrery-only measurements are in
[b1-preliminary.md](b1-preliminary.md).

The session has N Orrery → Facet → Ballast playback tracks, one additional
armed monitored stereo-input track with that chain, and a Ballast master
limiter. Compare confirmed maxima for anticipation on/off (target ≥3×).
Paced runs are dry tooling checks and must not be presented as device capacity.
The older Orrery-only measurements remain in [b1-preliminary.md](b1-preliminary.md).

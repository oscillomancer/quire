# B1: engine capacity

**Result (2026-10-21, MOTU M4 via PipeWire-JACK, 48 kHz / 64 frames, Core Ultra
5 225F, `powersave` governor, kernel 7.2.9-rt3, Marram as the synth):** with
anticipative processing the engine sustains **75 tracks** with zero xruns over
a confirmed 300 s run (N = 76 had 2 xruns and 9802 ahead misses; the renderer
ran at 78 % of real time at N = 64 and 163 % at N = 128). Without it, N = 29
passed once and failed its confirmation with one xrun (N = 30 had 6), so the
capacity is 28 to 29 tracks. The target "anticipative on ≥ 3× off" is missed:
75 against 28 to 29 is about 2.6×. REAPER on the same session sustains 82 to
83 ([b2.md](b2.md)).

The 2026-10-01 rows ran Orrery on kernel 7.2.7-zen1: 30 tracks with
anticipation, and N = 1 failed without it. The gain since then mixes the
synth change with the realtime kernel and cannot be split, since Orrery is
removed. The old N = 1 failures came at a small fraction of a core's average
load, which points at scheduling bursts more than DSP cost.

Notes: this workstation's `~/.config/pipewire/jack.conf.d` forces every JACK
client to quantum 128; the user lifted that for these runs, since the bench
makes an ordinary 64-frame request and rejects a different grant. The first
anticipative search of 2026-10-21 stopped at N = 128 because a starved
renderer's silent output read as a missing signal; its row is removed and the
search reran after that fix (revision bb2a099). The off-mode row reports
`dirty` because the earlier search had just appended to this file.

The session has N Marram → Yarrow → Sundew playback tracks (a pad: 8-note
chords, 3 unison voices, a ladder filter and tape drive), one additional armed
monitored stereo-input track with that chain, and a Sundew master peak
catcher. Rows recorded before 2026-10-21 ran Orrery; before 2026-10-18 Facet,
the EQ Yarrow replaced, and before 2026-10-19 Ballast, the compressor Sundew
replaced. Compare confirmed maxima for anticipation on/off (target ≥3×).
Paced runs are dry tooling checks and must not be presented as device capacity.

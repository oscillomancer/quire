## Reading the numbers

- **Notation** is solid: every phrase compiled; the one failure (waltz r3) was a
  first-attempt syntax error, `1: … | 2: … | 3: …` (bar numbers after pipes),
  fixed on the second compile from the error hint.
- **Descriptive with targets** is a tool-use floor, not a quality measure: the
  targets are in the prompt and every loss is 0.0. Use `--blind` from now on.
- **Blind descriptive** (description only, same scoring) is the
  discriminating baseline: misses on strings attack (2/3), noise-snare
  centroid (2/3) and formant-lead attack (1/3). Description → patch mapping is
  good but not perfect; these are the guide sections to improve.
- **Reference** (match a hidden render) passes the easy families (pluck bass
  3/3, noise snare 3/3, supersaw 2/3, pad 1/3) and fails the rest. The 30 % is
  **not** a clean model measurement: the harness/product issues below inflate
  failures, so no more reference runs until they are fixed.

## Product and harness issues found (queued in STATUS)

1. **Live instance ≠ its captured patch (high).** Reference acid bass, attempt 1:
   the agent's last render and a fresh session's render of the captured final
   patch differ (max 0.027; body ≈ 1.7 dB lower relative to the peak), which
   flips decay20 from 221 ms to 511 ms and the score from close to 11.2.
   The patch round-trips exactly through `patch.get`/`patch.set`, fresh
   renders are deterministic, and Orrery has no mutable static state, so some
   per-instance state set during the session (optimizer jobs, merges that add
   and remove slots) is not represented in the patch. What the agent hears is
   not what it saves. Repro: `build/eval/20261001T030803263327Z-synth-reference-hermes/reference.acid-bass-1/`
   (`tools.jsonl` holds the full call sequence; `renders/rd_17.wav` is the
   agent's render).
2. **Loss terms explode for small reference values.** `envelope.attack` reached
   5877 (a ~23 ms attack against a 0 ms reference), 85.7 and 9.9;
   `envelope.release` 43.6. decay20 floors its denominator at 10 ms; attack and
   release need the same (or a log-time distance). The optimizer shares this
   loss, so it also over-weights attack.
3. **The optimizer fails multi-parameter searches it should win.** Reference
   sub bass differs from the recipe only in `amp.release` (80 → 160 ms); all
   three agents ran 9-parameter auto-range searches (291 evaluations each) that
   never improved on the start (loss 3.994). A 1-D search from a fresh session
   reaches 0.11–1.04 depending on the search seed. Initial step size/range
   scaling, and a landscape that is not smooth in release.
4. **The agent cannot see the scored loss.** `compare` reports descriptor
   deltas, not the scalar reference loss or the pass threshold, so agents
   cannot tell how close they are. Expose `loss` (and its terms) in `compare`.
5. `job.wait` caps `timeout_s` at 30; agents asked for 300 and lost a call.
6. Notation could accept a bar number after `|` when it equals the next bar.
